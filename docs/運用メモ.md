# 運用メモ（Works IT Portfolio）

対象: 本リポジトリ（Firebase Hosting）＋ [rails-api](https://github.com/ishii-toshihiko/rails-api)（Cloud Run / Neon / Resend）  
目的: 障害時の切り分けと、品質ゲートの位置づけを短く残す。

案件向け概要は [CASE_STUDY.md](../CASE_STUDY.md) を参照。

## 想定案件・連絡

- **想定規模:** 小〜中規模の Rails API + React（認証・フォーム・メール・簡単な計測を含む Web）
- **連絡手段:** デモの [Contact フォーム](https://ishii-portfolio-front.web.app/contact)（実メールはサイト非公開）

## デプロイ

| 対象 | トリガ | 流れ |
|------|--------|------|
| フロント | `main` push | lint → knip → Playwright → build → Firebase Hosting |
| API | `main` push | RuboCop → RSpec → イメージ push → Secret 同期 → Cloud Run → `db:prepare` |

PR ではフロントの quality（lint / knip / e2e）のみ実行。

## ログ確認先

| 症状のあたり | 見る場所 |
|--------------|----------|
| API エラー・5xx | GCP **Cloud Logging**（Cloud Run サービス `rails-api`） |
| フロントが表示されない | Firebase Console → Hosting（デプロイ履歴・リライト） |
| お問合せが届かない | Cloud Logging（contacts）＋ Resend ダッシュボード。**本文全文はログに出さない**方針 |
| スキル公開内容 | DB の `skills`（公開）。下書きは `skill_drafts`（ユーザー別） |

## 障害時の切り分け（チェックリスト）

1. **画面そのもの**  
   - デモ URL が開くか。Hosting の最新デプロイが成功しているか。
2. **API 到達**  
   - Cloud Run のリビジョンが Ready か。ログに起動エラー・DB 接続エラーがないか。
3. **お問合せだけ失敗**  
   - 422（バリデーション）／429（レート制限）／502（Resend 失敗）を画面メッセージとログで確認。  
   - Secret（Resend 等）が欠けていないか（値はログに出さない）。
4. **スキル表示だけおかしい**  
   - 公開 `GET /v1/skills` の内容を確認。管理画面の下書きは公開に自動反映されない。
5. **認証・管理画面**  
   - トークン（access-token / client / uid）。オーナー公開は `SKILLS_OWNER_EMAIL` 一致が必要。

## 品質ゲートの位置づけ

- フロントの Playwright（`npm run test:e2e`）は **Hosting デプロイ前**に必須。  
- API の RuboCop / RSpec は **Cloud Run デプロイ前**に必須。  
- 「壊れたビルドを本番に載せない」ことが、このデモの運用上の約束事です。

## やらないこと（このメモの範囲外）

- 有料監視 SaaS の新規契約
- 実メールアドレスや API キーのドキュメントへの記載
